# 面向非技术用户的 HTML 编辑器：借鉴 PDF 业务版编辑器的功能清单与路线图

更新日期：2026-10-27

## 目标与判断标准

用户导入已有 HTML 页面，直接在预览中找到内容，用可视化操作或自然语言修改，并能确认结果、恢复误操作、完整带走成果。源码是可选的高级入口，不是主要工作界面。

借鉴的是成熟 PDF 编辑器的**文档操作体验**：容易定位、修改有预期、结果可复核、文件可完整交付。HTML 会响应不同屏幕宽度，且可能依赖 CSS、图片和脚本，因此不能照搬 PDF 的固定页坐标和自由拖拽方式。

优先级定义：P0 = 核心流程必须可靠；P1 = 非技术用户高频需要；P2 = 在核心流程稳定后加入；P3 = 经用户验证有需求后再做。状态只分为「已有」「待做」「条件性」，避免把原型功能误认为成熟能力。

## 当前基线

| 已有能力 | 当前边界 |
| --- | --- |
| 导入单个 HTML 或包含配套资源的文件夹 | 文件保存在浏览器内存；尚不能直接导入 ZIP 或完整导出文件夹 |
| iframe 实时预览、点击选中、高亮 | 对大型或动态生成的页面，定位与选中仍需验证 |
| 直接修改文字、通过本地 Ollama 修改元素 | AI 建议可先预览并选择应用/重试/放弃；修改范围和差异展示仍需加强 |
| 多步 Undo | 无 Redo、操作名称、跨刷新恢复或命名版本 |
| 默认收起源码、下载 HTML | 下载只包含 HTML，不自动打包 CSS、图片和脚本 |
| 导入脚本默认关闭，手动开启 | 复杂模块依赖及构建型项目尚不支持 |

## 分阶段实施计划

每阶段按表中 ID 拆成小任务。一个任务完成后更新本文件状态，并记录浏览器验证场景；不要仅凭代码编译标记完成。阶段顺序可依据真实用户反馈调整，P3 不自动进入开发。

### 阶段 1：让修改可审、可撤

实施 A1 → A2 → A3 → A4 → A6。先把 AI 响应存为候选，不立即改写 HTML；增加候选预览与接受/放弃。再把当前 Undo 扩展为具名操作与 Redo。

验收：导入样例页面，选中标题，请 AI 改写；在点击「应用」之前，原 HTML 和预览保持不变；放弃不产生历史记录；应用后可 Undo 和 Redo，且只影响批准的范围。整块删除有清晰确认与恢复路径。

进度（2026-10-27）：A1 已完成浏览器验收。用本地 Ollama 生成标题候选后，主预览与 Undo 状态保持不变；「重试」重新生成、「放弃」不留下历史、「应用」更新页面并可 Undo；在请求期间改选元素会忽略旧响应。阶段 1 的其余验收项仍待 A2–A6 实现。

### 阶段 2：让文件进得来、带得走

实施 B1 → B8 → B2 → B3 → B4 → B5 → B6。先建立资源清单与相对路径规则，确保未选中的内容不受编辑影响，再做 ZIP 导出/导入；最后完善多页面与交互模式。B7 与本阶段收尾一并考虑。

验收：导入含 HTML、CSS、图片和脚本的文件夹，修改标题，导出 ZIP；解压后在本地重新打开，样式和图片仍正确。缺失资源可见具体路径；脚本不开启时不执行，开启后行为和提示一致。

### 阶段 3：完成常见无代码编辑

实施 C1 → C2 → C3 → C4 → C5，再评估 C6、C7、C8。每个控件都通过同一套候选、应用、历史机制提交，避免可视化面板、AI 和源码产生不同步结果。

验收：不打开源码，用户能修改标题中的局部文字、按钮颜色和链接、替换图片及替代文字；所有修改在预览和导出文件中一致，并可逐步撤销。

### 阶段 4：提升长页面操作与交付质量

实施 D1 → D2 → D3 → D4，再做 D5、D6、D7、D8；补齐 A5。优先用真实长页面、移动端布局和含缺失资源的项目验证。

验收：用户可通过大纲或搜索快速定位元素，在三种预览宽度检查效果；导出前能看到资源和基本可访问性问题；意外刷新后可恢复未导出的本机草稿。

### 阶段 5：验证团队需求后再扩展

访谈至少数位实际使用者，确认是否存在跨角色审阅、评论和批量修改需求，再决定 E1–E4 的顺序与是否需要账号、权限和持久存储。没有证据时维持单人本地工具。

## 暂不照搬的 PDF 功能

- 固定页面坐标拖拽、盖章式定位：HTML 是响应式布局，直接照搬容易破坏手机视图。
- OCR、扫描件矫正、电子签章：与当前 HTML 编辑任务无直接关系。
- 一开始就做多人实时协作、权限与审批系统：先验证单人导入、修改、导出的完整流程。
- 自动执行任意导入脚本：脚本可能联网或改写页面；保持显式开关与隔离预览。
